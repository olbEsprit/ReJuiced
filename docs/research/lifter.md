# Аудит лифтера (демо Juiced), статически, без запуска игры

Ветка `juiced-lifter` в `ref/x86recomp-wt-lifter` (от `juiced` fef3d36). Эталон: Unicorn 2.1.4 (QEMU 5.0). Игру не запускал, `ref/x86recomp`, `build-demo`, `work/generated-demo` не трогал.

## 1. Покрытие (coverage.py, coverage.txt)
- Лифт: 11982 функции, 1 162 920 инструкций (с дублями inline), уникальных адресов 892 963. `.text` 2848 КиБ, дыр между функциями >0x40 всего 74 (~38 КиБ).
- Классы (уник. адреса): int 501k, ctl/stack 312k, x87 66k, MMX/3DNow 7370, SSE 5828.
- Различных форм (мнемоника + форма операндов) 581; входы оракул-тестов (`--int/--x87/--sse-test`) покрывают 362. Тестовых форм: int 15184, x87 4134 (из них 4000 цепочек), SSE 565.
- Не в оракул-входах (без unimplemented): push/pop/call/jcc/ret/leave/nop (по построению, ~290k сайтов), прочее мало: `unpcklps`/`unpckhps` (79 сайтов, 0 прямо достижимо), `rsqrtss` (12, исключён намеренно, отдельный тест), `clc/stc/cmc`, `ror m,i`, `lodsb/lodsd`, `scasd`, `cwde`, `fnsave/frstor/fnstenv/fldenv` (1-2), `ldmxcsr` 1, `bswap` 1. `unpcklps` проверил чтением `sse::UnpckPs`: по SDM верно. Почему генератор их не выдаёт, не выяснял.
- Прямая достижимость от entry 005CB426 по вызовам: 1906 из 11981 функций. Остальное идёт через vtable/колбэки, статически не определить, поэтому "menu->race" ниже оценён косвенно.

Настоящих ошибок семантики лифта в проверенном не найдено. Единственная находка: сломанные генераторы оракул-тестов (с 8780ec2 `lift_{x87,int,sse}_test` падали бы на первой форме на любом x86 хосте).
Ограничение: оракул проверяет Unicorn-совпадение там, где QEMU точен, поэтому слепые зоны: транс. функции, fprem/fscale, липкие флаги исключений, #GP на невыровненный movaps (QEMU не кидает; лифт кидает FATAL, это правильно). 80/64-бит: лифт моделирует 80 бит точно, PC/RC учитывает, предела "64-бит" нет, проверено в CW 037F/027F/007F.

## 4. Открытые вопросы (по важности)
1. MMX заявлен в CPUID (`edx=0x0783F9FF`, dispatch.cpp:463), комментарий "в поддерживаемых играх MMX нет" неверен для Juiced: 006732BD ставит флаг 0x20 по биту 23. Если диспетчер выбирает MMX-путь (006A0474, 006ACE5D, 005E7D9C...), будет FATAL на unimplemented movq. Варианты: снять бит MMX в CPUID (если есть Си-путь) или написать MMX. Проверить запуском.
2. `rcpps/rcpss` не реализованы (11 сайтов в SSE-библиотеке). Нужна аппроксимация Intel бит-в-бит, без железа проверить нечем (в оракуле QEMU считает точно).
3. `unpcklps/unpckhps` отсутствуют в генерируемых оракул-входах (79 сайтов).
4. Нет оракула для транс. функций и fprem/fscale: можно сверить точной арифметикой (fractions/mpmath) или на реальном x86.
5. Регрессионного теста на правку генератора нет: оракул-тесты на arm64 не собираются (CMake `x86_64` only, `MAP_FIXED_NOREPLACE`, `asm cld`).


## 6. Закрытие §4.1-4.3 (ветка juiced-lifter, 05.11.2026)
Коммиты: 69c0640 (rcp), f689add (MMX), 1b369a0 (oracle-формы из discovered).

**MMX (п.1).** Флаг по биту 23 (006732BD, бит 0x20) читает только 006733B3, и там MMX без 3DNow (0x80) ничего не выбирает: расширенный CPUID возвращает eax=0, 3DNow-таблица (0x69C2BB.., все `pf*`) недостижима. Второй потребитель - 00640681 (CPUID MMX + GetSystemInfo level>=5, реестр `DisableMMX`, `emms` на 0064071F), его зовут 005E7E69/005E7EA3 -> указатели 0x704AC4/0x704AC8 -> MMX-версия 005E7D4F (С-запасной путь 005E7B17). Остальные MMX-диапазоны (006A0430, 006A07F0, 006A12C0->006ADDA0, 006A2560, 006A69F0, 006A6B60, 006ACE30) - JPEG (jdsample/color, инит 006A0EC0 прямо достижим из 005CB426), на CPUID не завязаны: выбор по `do_fancy_upsampling` и размерам, так что снятие бита MMX их бы не спасло. Вывод: MMX достижим, реализован (вариант 1), CPUID не трогали. 0068F532/0068F65C - только в SSE-без-SSE2 таблице (672FE1, режим 3), при нашем CPUID (SSE2 есть) не выбирается; 6AB0C0.. и 0x695xxx - 3DNow, недостижимо.
Реализовано: movd/movq, padd{b,w,d,sw}, psub{w,d,sw}, pmullw/pmulhw/pmaddwd, packssdw/packsswb/packuswb, punpck{l,h}{bw,wd,dq}, pand/pandn/por/pxor, pcmpeq{w,d}/pcmpgtd, pmaxsw, psll{w,d,q}/psrl{w,d,q}/psra{w,d} с imm, emms. `src/runtime/mmx.h`: mm = sig регистров R0..R7, Enter (TOP=0, tags valid), Set (se=0xFFFF), Emms. x87-run больше не поглощает MMX (RunNeutral). После лифта в 10 достижимых функциях 0 unimplemented.
Оракул: `recomp_lift --mmx-test` + tests/lift_mmx_test.cpp (нативно, x86-64) + Unicorn-копия harness/uc_mmx_test (patch.py, uc.h RunMmx; MM-регистры в Unicorn no-op, идут через ST0-7). 655 форм x 400 проб = 0 расхождений (mm0-7, GPR, флаги, память, TOP, пустые теги после emms). Мутации (pmulhw >>15, emms без тегов) ловятся. tests/mmx_test.cpp - известные ответы, в ctest.
Не проверено: тег-слово «valid» при живом MMX (у нас выводится «special», видно только по fnstenv/fnsave до emms); регистровые/память-формы счётчика сдвига (в EXE нет, Unimpl); поведение при смеси x87 и MMX без emms.

**rcpps/rcpss (п.2).** Как rsqrt: точно округлённое 1/x (SoftFloat f32_div RNE), одинаково на любом хосте, в границе 1.5*2^-12. Спец: +-0 и денормалы -> +-inf, +-inf и |x| >= 1.1111111111010b*2^125 (tiny) -> +-0, NaN квантуется; MXCSR RC/FTZ не влияют. tests/sse_rcp_test: весь бинад [1,2) (2^23) точной целочисленной проверкой соседей, граница, масштабирование, спец. Реальное железо даёт другие (табличные) биты; бит-в-бит с Intel не проверялось и не проверяемо без железа. Из оракула rcp исключён (как rsqrt).

**unpcklps/unpckhps (п.3).** Причина «генератор не выдаёт» найдена: `--sse-test` отрабатывал до pass 1 и видел только Ghidra-входы, а вектор-библиотека (0x690000..) лежит среди 4557 discovered-функций. Теперь SSE и MMX формы берутся после discovery: SSE 565 -> 838 (54 формы unpck*ps), прогон Unicorn 300 проб: 0 расхождений; unpck* 1000 проб: 0. Заодно исключены FISTTP (x87) и PREFETCHW (не SSE-формы, давали Unimplemented). Both-NaN «выбор операнда» (QEMU vs SDM) вырос со 107 до 555 пар - тот же известный класс, не баг.
**Остаток:** int/x87-генераторы по-прежнему берут только Ghidra-входы (+2758 int-форм и 195 мусорных x87-последовательностей в discovered не проверены). tests/gl_draw_test.cpp не собирается (override в RecordingDevice), до моих правок, ctest: 17/18 + mmx, gl_draw Not Run.
Перезапуск MMX: `recomp_lift ... --mmx-test work/audit/forms/mmx_forms.cpp; cd harness && python3 patch.py && ./build.sh mmx && ./uc_mmx_test 400`.

## 7. int/x87 формы из discovered-функций (коммит выше 1b369a0)
