# Статический аудит демо Juiced: что упрётся дальше в HLE (меню -> загрузка -> гонка)

Метод. Бинарь: `game/demo/thq-v2-2005/game/Juiced.exe` (main; `binkw32.dll` и `eax.dll` рядом). Листинг лифта (893k инструкций, `demo-insns.txt`), `call [reg+off]` с признаком COM (последний push = this-регистр, vtable грузился из него), число push перед вызовом сверено с nargs HLE (`vt3.py`). Скрипты и сырьё: `work/audit/`. Динамика для сверки: `work/run-demo-trace.log` (02.11, 919 кадров attract, ничего не запускал). HLE-пути относительны `ref/x86recomp/src/runtime/`.
Важно: D3DX 9 слинкован в exe статически (~0x5DA000-0x690000), `d3dx9.dll` не импортируется, `hle/d3dx9.cpp` демо не касается. D3DX сам зовёт устройство через гостевой код (BeginStateBlock/Validate и т.п.).

## 1. Импорты (проверено)
- Juiced.exe: 212 импортов. Все именованные (около 180) (kernel32/user32/gdi32/advapi32/ole32/shell32/d3d9/dinput8/binkw32) есть в HLE; dsound `#1 #2 #6 #7 #9` реализованы (`hle/dsound.cpp:369-401`). `work/hle_impl.tsv` и `missing_imports.tsv` устарели (02.11 19:54): их «missing» по kernel32/user32/dsound уже закрыты.
- Не закрыто: wsock32 по ординалам, 22 из 28 (`#1 2 3 4 6 7 8 9 11 12 13 15 16 17 18 19 20 21 22 23 111 151`). `ws2_32.cpp:138-143` регистрирует только `ws2_32.dll`, алиаса нет; `shell_net.cpp:130-175` даёт wsock32 только `#115 #116 #57 #52 #14 #10` (там `#14` подписан htonl, на деле ntohl; безвредно).
- binkw32: все 11 импортов есть (`hle/binkw32.cpp`). `eax.dll`: `LoadLibraryA(eax.dll): not provided`, игра переживает (лог). Прочее по HLE не вылезло.
- `Direct3DShaderValidatorCreate9` (D3DX, `0x5FFDCC`, `0x6898CE`): d3d9.dll нет в `KnownDlls` (`hle/hle.cpp:58`), в трассе LoadLibrary/GetProcAddress на неё нет. Риска нет.

## 3. Дополнительно проверено (не риск)
- Reset `0x514460` (смена режима/AA в Options): `d3d9.cpp:805` пересоздаёт цепочку, сбрасывает состояния. CheckDeviceMultiSampleType для типа > 0 даёт NOTAVAILABLE (`:632`); игра спрашивает на `0x513272`, `0x513294`, затем просто без AA.
- Форматы: HLE знает DXT1-5, A8R8G8B8/X8R8G8B8/R5G6B5/A1R5G5B5/A4R4G4B4/L8/A8L8/D16/D24S8/R16F-R32F; нет V8U8, Q8W8V8U8, A2B10G10R10 (`FormatFromD3D`, `d3d9.cpp:32`). Игра их статически не проверяет (константы в CheckDeviceFormat: DXT1 `0x31545844`, DXT3 `0x33545844`, P8 `0x29`, глубина `0x02/1`), остальное идёт из таблицы в данных.
- Заглушки-«всегда ок»: TestCooperativeLevel (`:729` D3D_OK; Alt-Tab «потеря устройства» не эмулируется), GetRasterStatus (0/0), SetGammaRamp (no-op, игра зовёт `0x54`: яркость из Options не работает), EvictManagedResources, SetCursorPosition (no-op), Query::GetData (всегда 1, EVENT). Для окна/меню безвредно, яркость из Options визуально не сработает.
- Device caps: ветвлений игры по полям D3DCAPS9 надёжно из статики не получилось (копия caps лежит в объекте рендера, адресация косвенная). Не проверено.
- DSound: vtable-дыры (IDirectSound8: Compact, SetSpeakerConfig, VerifyCertification; Buffer8: Initialize, SetFX, GetObjectInPath; 3DBuffer: GetCone*). Игровые сайты `0x57F000-0x582000` неоднозначны по типу объекта (оффсеты `0x10/0x18/0x24/0x2C` совпадают у Buffer/3DBuffer/Sound8), достоверно не привязал. Низкий риск, не ранжирую.
- Музыка: `quartz: AddSourceFilter(.dsb): no decoder` в `work/run-demo.log` (05.11 21:51). Не D3D9, но видно: игра без музыки; гонку не роняет.

## 4. Что делать первым (по цене/эффекту)
1. п.1: заранее (VS=0 + PS) собрать FF-вершинный шейдер, иначе первый же пост-эффект упадёт. 2. п.9: алиас wsock32 -> ws2_32 (S, 10 минут). 3. п.6/7: UpdateTexture/UpdateSurface/ColorFill/GetRenderTargetData как прямой копией в host (S каждый), чтобы D3DX-пути не падали по имени. 4. Прогнать demo до гонки с `JUICED_KEYS` и смотреть, срабатывают ли п.1-2 (по трассе: DrawPrimitive/UP, SetRenderTarget на грань cube, usage 0x200).

Ограничения. Тип объекта по `call [reg+off]` выводится эвристикой (device надёжно только при `+0x7D0` рендер-объекта; D3DX-код и игровые C++-классы дают много совпадающих смещений). Границу «игра/D3DX» принял ~`0x5DA000` по адресам строк D3DX. `[Н]` = выведено без запуска.
